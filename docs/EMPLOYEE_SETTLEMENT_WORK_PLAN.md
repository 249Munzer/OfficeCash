# خطة عمل — نظام الاستحقاقات الذكي «محفظة الاستحقاق الحي»

**الغرض:** خطة عمل قابلة للتنفيذ لنظام مستحقات الموظفين والتصفية التلقائية في مكاتب التخليص، ضمن تطبيق OfficeCash.

**المعايير:** كل مهمة تنتهي بالتحقق التلقائي (`npm run lint` ثم `npm run build` ثم `npm test`) + اختبار يدوي وفق معيار القبول.

## المفهوم: «محفظة الاستحقاق الحي»

بدلاً من «تحديد طريقة دفع» (إعداد ثابت)، يُمنح كل موظف **محفظة استحقاق** يديرها **عقد استحقاق** من ٣ طبقات، ويغذيها **يوم عمل موثّق**، وكل تصفية تصدر **برقم توثيقي وبإثبات مزدوج**. بلا إدخال مزدوج — الاستحقاق يُشتق تلقائياً من معاملات النظام الموجودة.

### الطبقة ١ — مصدر الاستحقاق (Earn)
- **نسبة فقط** / **راتب فقط** / **نسبة + راتب** — النسب الجاهزة 25% / 40% / 50% + خيار **مخصص**، والراتب مبلغ يدوي.

### الطبقة ٢ — دورة التصفية (Cycle)
- يومية / أسبوعية / شهرية مع إمكانية **الدورة المزدوجة**: «نسبة يومية + راتب شهري» في عقد واحد يعملان كخطّي تصفية مستقلين.
- يوم استحقاق قابل للتخصيص (الجمعة، ٢٥ من الشهر...) لكل دورة.

### الطبقة ٣ — قناة الدفع (Pay Channel)
- من الصندوق نقداً / تحويل / خصم، مع تخصيص كل شيء من إعدادات الموظف.

### اليومية = «يوم عمل موثّق» (Documented Workday)
- **تسجيل الدخول = توقيع دخول** (Clock-in)، ثم **استراحة** مؤقتة، وعند الختام يحدّد: «في استراحة» أم «انتهى دوامي».
- خط زمني لكل يوم: دخول → استراحات → خروج → **إقفال يومي تلقائي** يسجَّل كلُّه في النظام.
- عند الإقفال: `الاستحقاق = Σ معاملات الموظف اليوم × النسبة` — يُحسب لحظياً وتظهر «محفظة اليوم» حية أمام الموظف.

### التصفية تتحرك في المحفظة لا تُحذف (Rolling Wallet)
حالة واحدة لكل استحقاق: **مستحق** → **قيد الانتظار (غير مؤكَّد)** → **مدفوع ومؤكَّد**.
- التصفية اليومية تُنشأ تلقائياً كـ «قيد الانتظار» → **بدون تأكيد الاستلام لا تُخصم من الإيراد ولا من الصندوق**، تبقى في المحفظة وتتصاعد كتنبيه.
- الراتب/النسبة الأسبوعية والشهرية تتراكم في المحفظة حتى يوم الاستحقاق.

### الإثبات المزدوج (Dual-Key Settlement)
- الإدارة **تُصرف** (تأكيد الخصم) ثم الموظف **يؤكّد الاستلام** → عندها فقط تُقيّد في السجل المالي.
- لكل تصفية **رقم تسلسلي + كوبون طباعة** (Voucher).

### نظام الإشعارات المتقن (Notification Center)
- جرس مركزي + شارات للطرفين (الإدارة والموظف).
- يومي: «استحقاق اليوم جاهز للتصفية» تُرسل للإدارة والموظف معاً.
- أسبوعي/شهري: تنبيهات **اقتراب الدفع** (قبل ٣ أيام، قبل يوم، يوم الاستحقاق).
- **تصعيد تلقائي** للمستحقات غير المؤكَّدة بعد مهلة قابلة للضبط.

### التكامل مع النظام الحالي
- الحساب من `entries` الموجودة — صفر إدخال مزدوج، وتكامل مباشر مع إغلاق اليوم (يُعرض «مستحقات معلّقة») ومع التقارير (يُتحول تبويب التصفية الشهري إلى «دفتر محفظة» لكل موظف) ومع مزامنة P2P.

## المرحلة ١ — النواة (النموذج + محرك الحساب)

### 1.1 `src/types.ts` — أنواع جديدة
- `CompensationMode = 'percentage' | 'salary' | 'percentage_and_salary'`
- `PayCycle = 'daily' | 'weekly' | 'monthly'`
- `AttendanceStatus = 'working' | 'break' | 'done'`
- `EmployeeContract` — النسبة (25/40/50/custom)، `requiresAttendance` (اختياري لكل موظف)، والراتب/الدورات تُكمل في المرحلة ٣
- `AttendanceRecord` — `clockIn`، استراحات `{start, end?}[]`، `status`، `clockOut?`
- `Settlement` — `type: 'daily_commission'`، `periodStart/End`، `grossRevenue`، `amount`، `status: 'pending'|'confirmed'`، `voucherNo`، طوابع التأكيد

### 1.2 `src/lib/settlement.ts` — دوال نقية
- `computeCommission(entries, rate)` — `Σ معاملات اليوم × النسبة`
- `buildDailySettlement(employee, entries, rate, today)` → `Settlement` بحالة `pending` + رقم تسلسلي `SF-YYYYMMDD-NNN`
- `employeeWallet(settlements, employeeId)` → { مستحق، قيد الانتظار، مدفوع }
- **معيار القبول:** اختبارات Vitest تغطي النسب الثلاث + custom، صفر معاملات، عدم تكرار الرقم التوثيقي.

### 1.3 `src/lib/attendance.ts` — دوال نقية
- `clockInFor`، `toggleBreak`، `finishDay`، `attendanceForDay`
- **معيار القبول:** اختبارات تغطي دخول بعد خروج، استراحة بلا نهاية، منع تكرار الدخول.

### 1.4 التخزين والمزامنة
- `src/lib/electron-storage.ts`: `load/saveAttendance` + `load/saveSettlements` (بصيغة `replaceXxx` مثل الإغلاقات) + إدراجها في `exportBackupJSON`/`importBackupJSON`/`clearAllData`/`resetToDemoData`
- `electron/main.js` + `electron/preload.js`: IPC endpoints جديدة بأسلوب `getXxx/saveXxx/replaceXxx`
- `src/hooks/useAppState.ts`: حالتان جديدتان (`attendance`, `settlements`) + مراجع + CRUD (`clockIn`، `updateAttendance`، `addSettlement`، `updateSettlement`) بسلاسل الحفظ نفسها

## المرحلة ٢ — اليوم الموثق + التصفية اليومية

### 2.1 `src/components/EmployeePortal.tsx` — «شريط اليوم»
- زر **تسجيل الدخول** (توقيع دخول) → يبدأ عدّاد الوقت الحي
- زر **استراحة / عودة** → يُسجَّل الفاصل الزمني
- زر **«انتهى دوامي»** → نافذة تلخيص: معاملات اليوم + **استحقاق اليوم المحسوب تلقائياً** (بطاقة كبيرة) → إنشاء `AttendanceRecord(done)` + `Settlement(pending)` + إشعار للطرفين فوراً
- بطاقة «محفظة اليوم» حية: الإيراد → النسبة → الاستحقاق، تُحدَّث مع كل معاملة
- **معيار القبول:** الموظف الذي ينهي دوامه دون معاملات لا تُنشأ له تصفية، والموظف العائد من استراحة يستأنف العدّاد.

### 2.2 التأكيد المزدوج (بدون تأكيد لا يُخصم)
- الموظف: نافذة «تأكيد استلام المستحقات اليومية» → قبول = `confirmed`، إغلاق = يبقى `pending`
- الإدارة: **شاشة `SettlementsScreen`** جديدة (مسار في الـ Sidebar) — قائمة المستحقات المعلّقة اليوم + زر **«تأكيد الصرف/الخصم»** + تاريخ لكل تأكيد
- الحالة `pending` لا تدخل في صافي الدخل ولا في إغلاق الصندوق إطلاقاً (تُخصم فقط عند `confirmed`)
- **معيار القبول:** تصفية غير مؤكَّدة تبقى خارج ملخص الإيراد/المصروف في لوحة التحكم والتقارير.

### 2.3 التنبيهات (نسخة V1 من المركز)
- جرس في `src/components/Header.tsx` + شارة: للإدارة «مستحقات معلّقة (N)»، وللموظف «استحقاقك ينتظر تأكيدك»
- قائمة منسدلة تعرض المعلّق
- **معيار القبول:** إغلاق اليوم وإنشاء تصفية يعرض الشارة فوراً دون إعادة تحميل.

### 2.4 إعدادات الموظف
- في `src/components/EmployeesManager.tsx`: قسم «عقد» لكل موظف — النسبة (أزرار 25/40/50 + حقل custom) + «يتطلب حضوراً يومياً؟»
- **معيار القبول:** حفظ وتعديل العقد يُبث عبر P2P ويُحمَّل عند إعادة التشغيل.

### 2.5 الربط العام
- تحديث `src/App.tsx` و`src/hooks/useNavigation.ts` + مفاتيح i18n AR/EN كاملة (مع اختبار تطابق اللغتين) + `broadcastP2PChange` بعد كل تغيير حضور/تصفية
